# Hiyoko Volume Mixer の使い方

**アプリごと・デバイスごとの音量／ミュート**を Stream Deck / Virtual Stream Deck の
キーから操作するプラグインです。Windows の Core Audio(WASAPI) を直接叩く
**内蔵の音声サーバー**を同梱しているため、**Elgato Volume Controller は不要**です。

「いま前面で鳴っているアプリだけ音量を下げる」「ゲームはそのままで BGM をミュート」といった操作を、ミキサーを開かずワンタッチでこなせます。

## 前提

- Windows 10 / 11
- Stream Deck アプリ（物理・Mobile・Virtual いずれも可）
- 追加のオーディオソフトは不要です。プラグインが起動時に内蔵サーバー
  (`hiyoko-audio-server.exe`) を自動起動し、`ws://127.0.0.1:1845` 経由で音量を操作します。
  - サーバー起動前の一瞬だけキーに **オフライン** と出ることがありますが、数秒で自動復帰します。

## 設計方針

**固定プロファイルは生成しません。各キーが独立したアクション**として動作します。
物理 Stream Deck・Stream Deck Mobile・Virtual Stream Deck のいずれにも、
好きなレイアウトでキーを並べて使えます。

## アクションの置き方

カテゴリ「Hiyoko Volume Mixer」の **アプリ音量ミキサー** を、キーにドラッグして配置します。
設定画面は **このキーだけの設定** と **全キー共通（全体設定）** に分かれています。

## このキーの設定

- **操作**: `音量を上げる` / `音量を下げる` / `ミュート切替`
  - 音量キーは **長押しで連続的に増減**します（押した瞬間に 1 段、その後は押している間くり返し）。
    ミュート切替は 1 回ごとのトグルです。
- **対象**:
  - `アプリ（自動スロット）`: 自動検出されたアプリのスロットを操作（既定）
  - `マスター（システム音量）`: システム既定の出力デバイス（マスター音量）を操作
- **スロット**: 操作するスロット位置（0 始まり。対象が「アプリ」のときのみ表示）

## もう一つのアクション：音声サーバー再起動

カテゴリには **音声サーバー再起動** というキーもあります。内蔵サーバーを手動で
再起動する保険用のボタンです。押すと `終了 → 起動し直し → 再接続確認` を行い、キー上に
「実行中…→ OK／失敗」を表示します。

内蔵サーバーはプラグインが自動で起動・監視し、万一終了しても自動で立ち上げ直すため、
通常このキーの出番はほぼありません。

### スロットという考え方

このプラグインの肝は、**特定のアプリを名指ししない**点です。

- いま音を出しているアプリが、アクティブな順に自動で並びます。
- キーには「アプリ名」ではなく **スロット番号（0, 1, 2…）** を割り当てます。
  - スロット 0 = いちばんアクティブなアプリ
  - スロット 1 = その次 …
- つまり「スロット 0 のキー」は、**そのとき先頭に来たアプリを自動で掴む**キーになります。
  アプリを起動し直して PID が変わっても、キー側の設定を直す必要はありません。
- **空きスロットでもキーは配置できます。** そのスロットにアプリが来れば自動で効き始めます
  （アプリが来るまではキーに `—` が表示されます）。

### 検出中のアプリ（プレビュー）

対象が「アプリ」のとき、設定画面に **スロット → アプリ** の対応がリアルタイム表示されます
（このキーが選んでいるスロットを強調）。ここでは全キー共通の操作として、

- **表示名の変更**: 各アプリ名を上書き（空欄＝検出名のまま）。同じアプリが出る全キーに反映されます。
- **同じ表示名でグルーピング**: 別々のセッションに **同じ表示名を付けると 1 つのグループにまとまり**、
  一括で操作されます（検出名が同じものは自動でまとまります）。例：光(SPDIF)入力とライン入力に
  同じ名前を付けて 1 キーでまとめて操作、など。
- **ミュートキーのアイコン変更**: アプリごとに、ミュートキーのアイコンを内蔵のモノクロ
  アイコン（音符／ゲーム／チャット／ブラウザ／動画／マイク／ヘッドホン／端末／ベル／スター／
  ハート）から選べます（既定はスピーカー）。
- **▲ / ▼ で優先順位の変更**: 上げたアプリほど小さいスロット番号（前の位置）に固定されます。
  常に同じ位置に置きたいアプリはこれでピン留めしてください。

## 全体設定（全キー共通）

スロットの並び順や音量ステップは全キーで一致している必要があるため、これらは
**Stream Deck のグローバル設定**として保存され、すべてのキーで共有されます。

- **検出対象**: `アクティブのみ`（再生中／直近使用のアプリ）/ `すべて`
- **同名アプリをまとめる**: 同じ表示名（または付けたラベル）のセッションを 1 グループにまとめる（既定 ON）
- **音量ステップ (%)**: 上げる／下げる 1 回あたりの増減幅（既定 5%）
- **更新間隔 (秒)**: 新しいアプリを検出するポーリング間隔（0.5〜10 秒、既定 1.5 秒）

## ミキサーの組み方

1 アプリ（＝1 スロット）につき 3 キー（ミュート / 音量↑ / 音量↓）を、**同じスロット番号**で割り当てます。

| キー | 操作 | スロット |
| --- | --- | --- |
| 1 | ミュート切替 | 0 |
| 2 | 音量を上げる | 0 |
| 3 | 音量を下げる | 0 |
| 4 | ミュート切替 | 1 |
| 5 | 音量を上げる | 1 |
| 6 | 音量を下げる | 1 |

アクティブなアプリが増減すると、その位置に来たアプリへ自動で切り替わります。
特定のアプリを常に同じ位置に置きたいときは、プレビューの ▲▼ で優先順位を固定してください。

## キーの見た目

キーは画像として自動描画されます（Stream Deck のタイトル文字は使いません）。

- **音量キー**: 上下のキーで **1 本のフェーダー**を分割表示します（上げる＝上半分、下げる＝下半分）。
  `＋` / `－` のバッジと現在音量（%）も表示されます。
- **ミュートキー**: アイコン（既定はスピーカー、アプリごとに変更可）。ミュート中は赤い斜線と
  「ミュート」、通常時は「通常」。
- **同名グループが複数**あるときは、名前の後ろに `×2` のように件数が付きます。
- **空きスロット**: アプリ名（または「スロット N」）と `—`。
- **オフライン**: 内蔵サーバーにまだ繋がっていないとき（起動直後の一瞬など）。

## 自動検出と保存

- 対象はセッション一覧のうち、`アクティブのみ` では **再生中＋直近約60秒以内に鳴っていたもの**を
  並べます。一瞬だけ鳴ったアプリも約1分は消えずにスロットに残ります。
  システム全体（processID 0）はアプリ一覧から除外されます。
- **各セッションは個別に識別**されます。同じプロセスが複数の音声セッションを持つ場合（例：光/SPDIF
  とライン入力）でも、まとめられず別々に操作できます。
- **同名グループへの操作はグループ内の全アプリに一括適用**されます。
- 音量は**出力デバイスごとに保存**され、保存値へ自動同期されます（例：Discord を 50% にしておけば
  次に検出されたとき自動で 50% に戻ります）。
  - **ミュートの復元はアプリの再出現時のみ**行います。定常時に Windows のミキサー等で手動解除しても
    勝手にミュートへ戻すことはありません。
- **ミュート中に音量を上げ／下げすると、ミュートは自動で解除されます**（音量を変えた＝聞きたい、
  という操作とみなすため）。

## 開発・インストール

必要なもの: Node.js（mise 管理）、Rust MSVC ツールチェイン、Visual Studio C++ Build Tools
（MSVC リンカ + Windows SDK）。Build Tools 未導入なら:

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

ビルド＆インストール:

```powershell
mise install                       # Node + Rust
.\scripts\install-dev-plugin.ps1   # Rustサーバー + プラグインをビルドして Stream Deck に配置
```

`install-dev-plugin.ps1` は Rust サーバー(`scripts/build-server.ps1`)とプラグインを両方ビルドし、
`hiyoko-audio-server.exe` を同梱した上でユーザーの Stream Deck Plugins フォルダへコピーします。
古いコードが残る場合は Stream Deck アプリを再起動してください。

個別タスク:

```powershell
mise run build-server   # cargo build --release ＋ exe をプラグインへコピー
mise run build          # プラグインを esbuild でバンドル
mise run check          # tsc --noEmit
mise run verify         # check + build-server + build
```

## つまずきやすいポイント

- **キーが「オフライン」のまま** → 内蔵サーバーが起動していない可能性。**音声サーバー再起動**キーを
  押すか、Stream Deck アプリを再起動してください。ビルド直後で `…sdPlugin/server/hiyoko-audio-server.exe`
  が無い場合は `install-dev-plugin.ps1`（または `mise run build-server`）を実行してください。
- **キーに `—`（空きスロット）が出る** → そのスロットに今アプリがいないだけです。対象アプリが
  音を出すと表示が戻ります。検出対象を「すべて」にすると無音アプリも並びに残せます。
- **狙ったアプリと違うものを操作してしまう** → スロットはアクティブ順に動的に並び替わります。
  位置を固定したいときはプレビューの ▲▼ で優先順位を設定してください。
- **別々に操作したいのにまとまる／逆にまとめたい** → 表示名を変えると分離、同じ表示名にすると統合
  されます（「同名アプリをまとめる」が ON のとき）。
